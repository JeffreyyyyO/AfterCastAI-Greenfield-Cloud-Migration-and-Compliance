## 3. What Sanitization Means

| Term | Meaning in This Certificate |
| :--- | :--- |
| Clear | Logical deletion + Trash / Recycle Bin emptied + link revoked + share revoked + access revoked. Applies to cloud stores where Purge is not available. Verification is Trash empty screenshot + link dead check + access list empty. |
| Purge | Cryptographic erase, secure wipe, factory reset with overwrite, or degaussing, where the method is verifiable. Applies to disks, laptops, NAS. Verification is wipe log + re-scan with no PII found. |
| Destroy | Physical destruction, where Clear + Purge are not verifiable, or where media is end-of-life. Applies to USB where wipe is not verifiable. Verification is destruction photo + disposal receipt + witness signature. |
| Sanitized | Method applied + verification completed + proof filed. A copy is sanitized only where all three are present. |
| Migrated, not deleted | Data moved to the After Architecture under the same lawful basis, with retention, before the Before Architecture copy was sanitized. Example: Hired 11 to S3 HR + Aurora HR. Flow 1 hashed ID to S3 + Aurora. Migrated data is not counted as deleted. |

**Standard:** NIST SP 800-88 Rev. 1, Media Sanitization. Clear / Purge / Destroy map to NIST Clear / Purge / Destroy. Method selection follows media type, not convenience.

**What is not sanitization:** Moving a file to Trash without emptying Trash. Revoking a link without deleting the file. Deleting a CSV without deleting the model trained on it. Deleting a Sheet without deleting Gmail copies. Renaming a folder. Moving a USB to a locked drawer. Any of those leaves a copy present.

### 12.1 Numbering System — Rules

- Phase 0 docs use `0.x`, sequential from `0.0` to `0.18`, with no gaps. `0.0` is prerequisites. `0.1` is Shadow IT Inventory. `0.2` is Audit Report. `0.3` is RoPA. `0.4` is DPIA — HR. `0.5` is DPIA — Profiling. `0.6` is Business Case. `0.7` is Foundational Roadmap. `0.8` is Roadmap. `0.9` is Glossary. `0.10` is Appendix B. `0.11` is Classification. `0.12` is Retention. `0.13` is Compliance Mapping. `0.14` is DPA + TIA. `0.15` is Privacy Notice. `0.16` is this file, Legacy Sanitization Certificate. `0.17` is Appendix G. `0.18` is Appendix H.
- Phase guides use `phase-N`, for example `phase-1-organization-identity.md`. They are not `0.x`, because they belong to Phases 1 to 10, not Phase 0.
- Evidence uses `phase-N`, for example `evidence/sections-after/phase-1/`. It is not `0.x`.
- Terraform uses `phase-N`, for example `terraform/phases/phase-1/`. It is not `0.x`.
- File names keep bare `before` / `after` where they appear: `audit-before`, `sections-after`, `0.18-appendix-h-before-vs-after.md`.

## 13. Rules — 1 Fact, 1 Name

- **1 Fact, 1 Name:** Character, Location, Count, DataClass match exactly across Inventory, Diagram, Findings, RoPA, DPIA, Tables, Appendix B, Roadmap. Auditor Ctrl+F finds the same name everywhere.
- **One fact, one file:** Glossary lives once in `0.9-glossary.md`. Compliance mapping lives once in `0.13-compliance-mapping.md`. Other docs link.
- **Separation:** `0.0-prerequisites.md` is the operational checklist. `0.7-foundational-roadmap.md` is The Foundation, the story and narrative. They are separate files.
- **Audit Report name:** Security and Privacy Audit Report, or Audit Report, with no number in the name.
- **Phase vs Wave vs Section:** Phase = 0 to 10 roadmap block, 11 Phases. Wave = 1 to 5 delivery increment, 5 Waves. Section = single build unit inside a Phase, 56 Sections in the Roadmap.
- **Naming:** `phase-1` format throughout. `terraform/phases/phase-1/`, `docs/phases/phase-1-...`, `evidence/sections-after/phase-1/`.
- **Numbering:** All doc filenames use the numbering system in Sec 12.1. Phase 0 docs use `0.x`. Phase guides, evidence, and Terraform use `phase-N`.
- **Email separator:** Em-dash style. `Personal Gmail: funmi.personal@gmail.com — Funmi Daniels (Sales, AE)` and `WorkMail: funmi.daniels@aftercast.ai — Funmi Daniels (Sales, AE)`.
- **Fictional Gmail disclaimer:** The disclaimer appears on: cover, note after title, full disclaimer in Sec 2.2, footnote in Sec 4 / Table 3, footer, README, Appendix B.
- **Terminology:** DataClass tags are Restricted-PII and Restricted-PII + Sensitive. SPII is not a DataClass tag. Node (7-Node model) is used consistently. Transit A-F is used. Lifecycle Phases are: Collection, Ingestion, Distribution, Access, Replication, Retention.
- **After Architecture / Before Architecture:** Doc sections, titles, and table columns use After Architecture / Before Architecture. File names, in-AWS custom configs, resources, tags, and service names keep bare `after` / `before`.
- **RetentionDays:** Only 90, 180, 365, 1825. Pseudonymisation is a technique.
- **Counts:** The count is 143 total = 11 hired + 132 rejected.
