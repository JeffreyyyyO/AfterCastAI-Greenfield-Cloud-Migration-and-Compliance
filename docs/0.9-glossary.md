## 1. Purpose and Scope

This file is Appendix C. It is the Glossary. It is the canonical single-source definitions file for terms in the Audit Report, RoPA, DPIAs, Classification Policy, Retention Policy, Business Case, and Phase guides.

One fact, one file: Glossary lives once here. Compliance mapping lives once in `0.13-compliance-mapping.md`, Appendix F. Other docs link to this file for a definition. Other docs contain a short reference to a term, not a second full definition.

1 Fact, 1 Name: Character, Location, Count, DataClass match exactly across Inventory, Diagram, Findings, RoPA, DPIA, and Terraform. Where another doc and this glossary contain the same fact, the wording in this glossary and in the Audit Report is the canonical wording.

**Phase**
A learning / building block, Phases 0 to 10, 11 Phases. Phase 0 has 11 Sections. Total is 56 Sections.

Data that identifies a person, directly or indirectly. Flow 1: Name, Email, Phone, Delivery Address, Loyalty ID, Purchase History. Flow 2: CV, NIN, BVN, Passport, Home Address, Bank Details. PII is not a DataClass tag. Restricted-PII or Restricted-PII + Sensitive are the DataClass tags.

**Pseudonymisation**
Technique, not a RetentionDays value, not declassification. Email → `sha256_hashed_id` with salt, before training, with mapping separate. Pseudonymised data is still personal data, still Restricted-PII, until truly anonymised and re-identification is impossible. See DPIA — Profiling, `0.5-dpia-luxemart-profiling.md`, Sec 9.

**Public**
DataClass tag. Public marketing, no PII, can be published. Examples: Public website copy, public blog, public job advert with no applicant data.

### Numbering System — Rules

- Phase 0 docs use `0.x`, sequential from `0.0` to `0.18`, with no gaps. `0.0` is prerequisites. `0.1` is Shadow IT Inventory. `0.2` is Audit Report. `0.3` is RoPA. `0.4` is DPIA — HR. `0.5` is DPIA — Profiling. `0.6` is Business Case. `0.7` is Foundational Roadmap. `0.8` is Roadmap. `0.9` is this file, Glossary. `0.10` is Appendix B. `0.11` is Classification. `0.12` is Retention. `0.13` is Compliance Mapping. `0.14` is DPA + TIA. `0.15` is Privacy Notice. `0.16` is Legacy Sanitization Certificate. `0.17` is Appendix G. `0.18` is Appendix H.
- Phase guides use `phase-N`, for example `phase-1-organization-identity.md`. They are not `0.x`, because they belong to Phases 1 to 10, not Phase 0.
- Evidence uses `phase-N`, for example `evidence/sections-after/phase-1/`. It is not `0.x`.
- Terraform uses `phase-N`, for example `terraform/phases/phase-1/`. It is not `0.x`.
- File names keep bare `before` / `after` where they appear: `audit-before`, `sections-after`, `0.18-appendix-h-before-vs-after.md`.

## Rules — 1 Fact, 1 Name

- **1 Fact, 1 Name:** Character, Location, Count, DataClass match exactly across Inventory, Diagram, Findings, RoPA, DPIA, Tables, Appendix B, Roadmap. Auditor Ctrl+F finds the same name everywhere.
- **One fact, one file:** Glossary lives once in this file, `0.9-glossary.md`. Compliance mapping lives once in `0.13-compliance-mapping.md`. Other docs link.
- **Separation:** `0.0-prerequisites.md` is the operational checklist. `0.7-foundational-roadmap.md` is The Foundation, the story and narrative. They are separate files.
- **Audit Report name:** Security and Privacy Audit Report, or Audit Report, with no number in the name.
- **Phase vs Wave vs Section:** Phase = 0 to 10 roadmap block, 11 Phases. Wave = 1 to 5 delivery increment, 5 Waves. Section = single build unit inside a Phase, 56 Sections in the Roadmap.
- **Naming:** `phase-1` format throughout. `terraform/phases/phase-1/`, `docs/phases/phase-1-...`, `evidence/sections-after/phase-1/`.
- **Numbering:** All doc filenames use the numbering system above. Phase 0 docs use `0.x`. Phase guides, evidence, and Terraform use `phase-N`.
- **Email separator:** Em-dash style. `Personal Gmail: funmi.personal@gmail.com — Funmi Daniels (Sales, AE)` and `WorkMail: funmi.daniels@aftercast.ai — Funmi Daniels (Sales, AE)`.
- **Fictional Gmail disclaimer:** The disclaimer appears on: cover, note after title, full disclaimer in Sec 2.2, footnote in Sec 4 / Table 3, footer, README, Appendix B.
- **Terminology:** DataClass tags are Restricted-PII and Restricted-PII + Sensitive. SPII is not a DataClass tag. Node (7-Node model) is used consistently. Transit A-F is used. Lifecycle Phases are: Collection, Ingestion, Distribution, Access, Replication, Retention.
- **After Architecture / Before Architecture:** Doc sections, titles, and table columns use After Architecture / Before Architecture. File names, in-AWS custom configs, resources, tags, and service names keep bare `after` / `before`.
- **RetentionDays:** Only 90, 180, 365, 1825. Pseudonymisation is a technique.
- **Counts:** The count is 143 total = 11 hired + 132 rejected.
- **Logs vs PII:** Logs + deletion proof are kept 6 years in Glacier Deep Archive. PII is not kept 6 years. Flow 1 PII is deleted 365d. Flow 2 rejected is deleted 180d, hired is kept 6y.
- **Cost:** Test-environment cost with gating is $0 to $3 per month for most work. Production steady-state is $850 to $1,450 per month as in Business Case.
