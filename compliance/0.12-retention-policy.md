## 2. Principles

1. **Storage Limitation:** GDPR Art 5(1)(e), NDPA Sec 24(d). Personal data is kept no longer than necessary for the purpose for which it was collected.
2. **1 Fact, 1 Name:** RetentionDays matches exactly across Audit, RoPA, DPIAs, Classification Policy, Terraform, and this policy. No new RetentionDays are invented.
3. **RetentionDays are numbers, not techniques:** RetentionDays = 90, 180, 365, 1825. Pseudonymisation is a technique, not a RetentionDays value. RetentionDays is not Pseudonymised.
4. **Logs are not PII:** Logs + deletion proof are kept 6 years for audit. PII is not kept 6 years. Where a log contains PII, it is redacted before it is kept 6 years. Customer PII is deleted after 365 days (Flow 1) / 180 days rejected (Flow 2) / 6 years hired (Flow 2). Logs are kept 6 years. PII is not kept 6 years.
5. **Automatic deletion:** Retention is enforced by S3 Lifecycle + AWS Backup, not by manual deletion. Manual deletion is a backup, not the control.
6. **Proof, not trust:** Every deletion has proof: S3 Inventory + CloudTrail DeleteObject + Macie + Lifecycle log, kept 6 years in Glacier Deep Archive, with hashed ID + DSR ID only, not raw PII.
7. **No copy survives retention:** Deletion deletes all copies: S3, Aurora, Model, Mapping, Backup, Logs, Trash, GitHub history, WhatsApp backup, Dropbox Trash. Deleting the CSV but keeping the model is not deletion. See Sec 5.5.

## 3. RetentionDays — Canonical Values

**Only these 4 values exist for personal data. No other RetentionDays are invented, for example 30 or 60 for PII, unless DPO approves and updates this policy.**

| RetentionDays | What It Means | Used For |
| :--- | :--- | :--- |
| 90 | 90 days | Internal logs, temporary files, pre-signed URL logs, WAF logs, where no PII, or pseudonymised only. Transition to Glacier Deep Archive after 90 days where needed for audit. |
| 180 | 180 days, 6 months | Flow 2 Rejected Applicants, 132 rejected. NDPA says rejected candidate data is kept no longer than 6 months. |
| 365 | 365 days, 1 year | Flow 1 LuxeMart raw CSV, 12,000 EU. AfterCast retention for forecasting, as per DPA. |
| 1825 | 1825 days, 6 years | Flow 2 Hired Employees, 11 hired, employment / tax. Logs + deletion proof, 6 years, for audit, with PII not kept 6 years, except hired 11 who are kept 6 years by law. |

**Tagging:**

- S3 Tag: `RetentionDays = 365`, `RetentionDays = 180`, `RetentionDays = 1825`, etc.
- S3 Tag: `DataClass = Restricted-PII` or `Restricted-PII + Sensitive`, etc.
- Both tags are required. Bucket Policy denies PutObject where either tag is missing. See Classification Policy Sec 8.

## 5. Lifecycle — Deletion

### 5.1 S3 Lifecycle, Flow 1

- Day 0: Intake, S3 PutObject, Tags: `DataClass = Restricted-PII`, `RetentionDays = 365`, `Flow = Flow-1`
- Day 0 to 365: S3 Standard, KMS, Versioning, Lake Formation sales-group only
- Day 365: S3 Lifecycle DeleteObject, Versioned Delete Marker, S3 Inventory + CloudTrail DeleteObject + Macie proof to Glacier Deep Archive
- Day 365 to 1825: Proof in Glacier Deep Archive, hashed ID only, PII not kept
- Day 1825: Delete proof, with proof of proof

### 5.2 S3 Lifecycle, Flow 2 Rejected

- Day 0: Application, CV only, Tags: `DataClass = Restricted-PII + Sensitive`, `RetentionDays = 180`, `Flow = Flow-2`, `Status = Applicant`
- Day 0 to 30: S3 Standard, KMS, Lake Formation hr-group only
- Day 30: S3 Lifecycle Transition to Glacier, where rejected and 30 days passed
- Day 180: S3 Lifecycle DeleteObject, S3 Inventory + CloudTrail + Macie proof to Glacier Deep Archive
- Day 180 to 1825: Proof in Glacier Deep Archive, hashed ID only
- Day 1825: Delete proof, with proof of proof

### 5.3 S3 Lifecycle, Flow 2 Hired

- Day 0: Application, CV only, Tags: `DataClass = Restricted-PII + Sensitive`, `RetentionDays = 1825`, `Flow = Flow-2`, `Status = Hired`
- Day 0 to 365: S3 Standard, KMS, Lake Formation hr-group only
- Day 365: S3 Lifecycle Transition to Glacier
- Day 1825: S3 Lifecycle Transition to Deep Archive, then Delete, with proof
- Day 1825 to 3650: Proof in Glacier Deep Archive, hashed ID only, then delete proof

### 5.4 Aurora + Model + Mapping

- Aurora: Delete row for `hashed_id` on S3 Lifecycle Delete, via Lambda, with Aurora deletion log. No orphan rows.
- Mapping: Delete mapping row for `hashed_id` on S3 Lifecycle Delete, via Lambda, with S3 Inventory proof. No orphan mapping.
- Model: On DSR or on Retention expiry, mark model version tainted, retrain without deleted hashed IDs, create new model version, with retraining log. Deleting CSV but keeping model is not deletion.

### 5.5 What Is Not Deletion

- Moving to Trash is not deletion. Dropbox Trash, Gmail Trash, WhatsApp backup, GitHub history, QNAP Old, USB, all are emptied, with proof.
- Deleting the CSV but keeping the model is not deletion.
- Deleting the Sheet but keeping Gmail BVN List is not deletion.
- Deleting Gmail Inbox but keeping Gmail Sent is not deletion.
- Deleting QNAP but keeping USB is not deletion.
- All copies are deleted, with proof, in all stores: S3, Aurora, Model, Mapping, Backup, Logs, Trash, GitHub history.

## 7. Terraform Enforcement — Retention Enforcement, Not Only Policy

Policy alone does not delete. Terraform + S3 Lifecycle + AWS Backup enforce. The following is in Phase 1 + Phase 2 Terraform.

### 7.1 S3 Lifecycle

- Flow 1: `s3://aftercast-prod-restricted-pii-eu-west-1/` — Lifecycle: Delete raw CSV after 365 days, Transition logs to Glacier Deep Archive after 90 days, Keep logs 6 years, PII not kept 6 years.
- Flow 2: `s3://aftercast-hr-restricted-pii-eu-west-1/` — Lifecycle: Rejected 132, Transition to Glacier after 30 days, Delete after 180 days. Hired 11, Transition to Glacier after 1 year, Transition to Deep Archive after 6 years, Delete after 1825 days.
- Both buckets: Versioning ON, KMS CMK, Object Lock ON for audit logs, Block Public Access ON, VPC Endpoint only, TLS 1.2 only.

### 7.2 AWS Backup

- Flow 1: AWS Backup, KMS, `eu-west-1`, Retention 365 days, same as S3, Delete backup after 365 days, with proof. No backup kept beyond retention.
- Flow 2: AWS Backup, KMS, `eu-west-1`, Retention 180 days for rejected, 1825 days for hired, MFA Delete ON, Versioning ON, Delete backup after retention, with proof. No backup kept beyond retention.
- All: Backup vault in `eu-west-1`, `eu-west-2` backup / DR only, KMS CMK, Object Lock ON, CloudTrail audit.

### 7.3 Bucket Policies + SCPs

- Bucket Policy denies PutObject where `DataClass` or `RetentionDays` tag is missing. See Classification Policy Sec 8.
- Bucket Policy denies PutObject where `RetentionDays` is not `365` for Flow 1, or not in `180, 1825` for Flow 2.
- SCP denies any action in any region except `eu-west-1` and `eu-west-2` for PII. Denies `us-*` for PII.
- SCP denies `s3:DeleteBucket` without MFA Delete for HR + Prod buckets.

### 7.4 Where Lifecycle Misses Deletion

Where S3 Lifecycle does not delete on time, Engineering + DPO are notified within 24h. Manual deletion via DSR role, with proof, is backup. The missed Lifecycle is a finding. It is logged in RoPA Change Log.

## 8. Legal Hold — When Retention Is Paused

Legal hold pauses deletion. Only DPO + CEO can place a legal hold. Legal hold is in writing, with:

- Reason: Litigation, investigation, NDPC / ICO request, etc.
- Scope: Which `hashed_id`, which Flow, which date range
- Duration: Start date, end date, or until DPO lifts hold
- Who is notified: Engineering, HR, Sales, as needed

**Rules for legal hold:**

- Legal hold overrides Lifecycle. S3 Lifecycle is paused for held objects, via Object Lock Legal Hold.
- Legal hold does not allow new collection. It only pauses deletion of existing data.
- Legal hold is reviewed monthly by DPO. Where hold is no longer needed, DPO lifts it, and Lifecycle resumes.
- Legal hold is logged in RoPA Change Log, with DPO + CEO signatures.
- No legal hold exists in the Before Architecture. No legal hold is in place for Flow 1 + Flow 2 as of 18th Oct 2026, unless DPO places one in writing after this policy.

## 9. Exceptions — When Retention Can Be Extended

Exceptions are rare. Only DPO + CEO can approve an exception, in writing, with:

- Reason: Legal Obligation, for example tax law requires 6 years for hired, not 180 days for rejected.
- Scope: Which data, which Flow, which RetentionDays, new RetentionDays
- Duration: Start date, end date
- Risk: What is the risk of keeping longer, and how is it mitigated?

**What Is Not an Exception:**

- We might need it later is not an exception.
- We forgot to delete it is not an exception, it is a breach.
- The model needs more data is not an exception, unless LuxeMart DPA + DPIA + DPO approve it, and pseudonymisation + minimisation are proven.
- The Sheet is still open is not an exception, it is a breach.

**No exceptions exist for Flow 1 + Flow 2 as of 18th Oct 2026, except hired 11 kept 6 years by law, which is already in this policy.**

### 15.1 Numbering System — Rules

- Phase 0 docs use `0.x`, sequential from `0.0` to `0.18`, with no gaps. `0.0` is prerequisites. `0.1` is Shadow IT Inventory. `0.2` is Audit Report. `0.3` is RoPA. `0.4` is DPIA — HR. `0.5` is DPIA — Profiling. `0.6` is Business Case. `0.7` is Foundational Roadmap. `0.8` is Roadmap. `0.9` is Glossary. `0.10` is Appendix B. `0.11` is Classification. `0.12` is this file, Retention. `0.13` is Compliance Mapping. `0.14` is DPA + TIA. `0.15` is Privacy Notice. `0.16` is Legacy Sanitization Certificate. `0.17` is Appendix G. `0.18` is Appendix H.
- Phase guides use `phase-N`, for example `phase-1-organization-identity.md`. They are not `0.x`, because they belong to Phases 1 to 10, not Phase 0.
- Evidence uses `phase-N`, for example `evidence/sections-after/phase-1/`. It is not `0.x`.
- Terraform uses `phase-N`, for example `terraform/phases/phase-1/`. It is not `0.x`.
- File names keep bare `before` / `after` where they appear: `audit-before`, `sections-after`, `0.18-appendix-h-before-vs-after.md`.

## 16. Rules — 1 Fact, 1 Name

- **1 Fact, 1 Name:** Character, Location, Count, DataClass match exactly across Inventory, Diagram, Findings, RoPA, DPIA, Tables, Appendix B, Roadmap. Auditor Ctrl+F finds the same name everywhere.
- **One fact, one file:** Glossary lives once in `0.9-glossary.md`. Compliance mapping lives once in `0.13-compliance-mapping.md`. Other docs link.

- **Audit Report name:** Security and Privacy Audit Report, or Audit Report, with no number in the name.
- **Phase vs Wave vs Section:** Phase = 0 to 10 roadmap block, 11 Phases. Wave = 1 to 5 delivery increment, 5 Waves. Section = single build unit inside a Phase, 56 Sections in the Roadmap.
- **Naming:** `phase-1` format throughout. `terraform/phases/phase-1/`, `docs/phases/phase-1-...`, `evidence/sections-after/phase-1/`.
- **Numbering:** All doc filenames use the numbering system in Sec 15.1. Phase 0 docs use `0.x`. Phase guides, evidence, and Terraform use `phase-N`.
- **Email separator:** Em-dash style. `Personal Gmail: funmi.personal@gmail.com — Funmi Daniels (Sales, AE)` and `WorkMail: funmi.daniels@aftercast.ai — Funmi Daniels (Sales, AE)`.
